# SeaBattle

## Запуск

Unity **6000.5.10f1**, Node.js **22+**. Сервер запускается вручную из отдельного репозитория в папке Server:

```powershell
cd Server
npm ci
npm start
```

В Unity откройте Assets/Scenes/SeaBattle.unity и нажмите Play. Один экземпляр приложения — один игрок.
Первый игрок вводит имя и нажимает «Создать», второй — то же имя и «Присоединиться».
Имя: ровно 8 латинских букв или цифр, регистр учитывается. Занятое имя отклоняется; присоединение не создаёт новую комнату.
Для второго игрока используйте отдельный билд. По умолчанию оба клиента подключаются к ws://127.0.0.1:2567.
Для разных компьютеров укажите адрес компьютера с сервером в ConnectionConfig.asset.

После подключения показываются своё поле с кораблями и поле соперника с результатами выстрелов.
Второй игрок запускает партию. Попадание тоже передаёт ход. Сервер определяет таймер, потопление и победителя.
После завершения открывается попап «Победа!» или «Поражение». Кнопка «В меню» возвращает в лобби.
«Выйти» возвращает к выбору комнаты; добровольный выход во время игры означает поражение.

## Архитектура

- Bootstrapper создаёт ProjectContext, задаёт настройки приложения и запускает LoadingState.
- GameInstaller связывает сервисы, StateMachine, UIManager и фабрики моделей через Zenject.
- LoadingState инициализирует сервисы; GameState открывает попап комнат.
- Инициализация ColyseusTransportService не подключает игрока: соединение открывается кнопкой попапа или при восстановлении сохранённой сессии.
- RoomPopupModel создаёт/находит комнату; ошибки и ожидание отображаются через UniRx.
- BattlePopupModel связывает транспорт, MatchService, время и отображение боя.
- MatchService принимает серверную Schema; клиент не рассчитывает попадания или победителя.
- BoardView создаёт клетки из сохранённого префаба по серверному размеру поля.
- UIManager управляет префабами попапов; PrimeTween выполняет появление окна.
- Ожидающий выстрел блокирует новые команды до ответа и соответствующей ревизии состояния.
- Colyseus автоматически синхронизирует Schema; StateView скрывает корабли соперника.
- Сервер: index.ts → app.config.ts → BattleRoom → BattleGame.

## Сеть и восстановление

Сообщения fire/commandResult передаются объектами Colyseus. Запрос serverTime при входе и каждые 2 секунды синхронизирует таймер с поправкой на половину времени запроса. Если ответов нет 8 секунд, клиент закрывает старое соединение и пытается восстановить его. Интервалы задаются в ConnectionConfig. Подробности — [PROTOCOL.md](PROTOCOL.md).

Быстрые клики отправляют одну команду. Ответ и патч могут прийти в любом порядке: интерфейс ждёт оба.
При задержке ответа выводится, что результат неизвестен; новый выстрел остаётся заблокированным. Клиент повторяет ту же команду с прежним commandId. Сервер хранит результаты принятых и отклонённых команд; повтор не меняет исход и не расходует ход.

При обрыве стрельба отключается. Colyseus сохраняет место игрока на 120 секунд после обнаружения разрыва сервером (ReconnectGraceSeconds). Повторные попытки идут с интервалом 1 секунда. Таймер партии продолжает работать. По истечении срока игрок проигрывает; если партия ещё не началась, его место освобождается. Клиент также ограничивает попытки восстановления этим сроком.

SessionService сохраняет в PlayerPrefs адрес, комнату, идентификатор игрока, reconnectionToken и незавершённый выстрел до его отправки. После пересоздания приложения или перезапуска сцены GameState автоматически восстанавливает сессию. Новый сокет получает полную приватную Schema, а ожидающий выстрел отправляется с прежним ID для уточнения результата. Обработчики старых соединений игнорируются; старые ревизии не принимаются. «В меню»/«Выйти» очищают сохранённую сессию и означают добровольный выход.

Редактор и standalone используют разные ключи сохранения; виртуальные редакторы MPPM различаются путём проекта. Для двух билдов на одном компьютере задайте разные аргументы, например `SeaBattle.exe --player-profile=second`, иначе они используют один сохранённый профиль.

Комнаты и результаты команд хранятся в памяти одного серверного процесса. После перезапуска сервера восстановить партию нельзя; если ответ был потерян, клиент не объявляет такой выстрел непринятым. При недоступной сессии предлагается начать новую партию. Корабли прямые, между разными кораблями остаётся зазор, включая диагонали.

## Панель отладки

Кнопка «Отладка сети» слева сверху открывает и сворачивает панель. У каждого экземпляра приложения своя панель и эмулятор сети.

- Задержка и разброс задаются в миллисекундах (0–10000), потери и дубликаты — в процентах (0–100). «Применить настройки» меняет обработку новых сообщений в обе стороны. Ожидающие сообщения сохраняют рассчитанные сроки. Seed задаёт последовательность случайных решений; одинаковые seed и порядок трафика дают одинаковую эмуляцию.
- «Разорвать» включает тихую потерю всех сообщений. Событие отключения не отправляется: клиент обнаруживает обрыв по heartbeat примерно через 8 секунд. «Подключить» снова разрешает доставку с текущими параметрами потерь/задержек, после чего работает обычное восстановление. При потерях 100% связь по-прежнему невозможна.
- «Пересоздать клиент» уничтожает ProjectContext, сервисы и UI, затем заново загружает сцену. Сессия и pending-команда восстанавливаются из PlayerPrefs. Настройки эмуляции и лог сбрасываются к значениям ConnectionConfig.
- «Перезапустить сцену» пересоздаёт сцену и игровые окна, сохраняя сервисы и настройки эмуляции. Ожидающие сообщения старого соединения отменяются.
- «Лог сообщений» включает запись попыток отправки/получения, доставок, потерь, дубликатов и отбрасывания старых сообщений. Видны последние 14 записей; «Очистить» удаляет их. Токены восстановления и скрытые данные поля не записываются.

Эмуляция работает в клиентском транспорте над игровыми сообщениями fire, commandResult, serverTime, error и снимками Schema. Бинарные дельты Colyseus декодируются штатным SDK; эмулятор передаёт игре независимые копии состояния, поэтому задержанная Schema не меняется за её спиной. На heartbeat также проверяется актуальный снимок, чтобы потерянный последний патч восстановился даже после окончания партии. HTTP-создание комнаты не получает искусственные потери, но при тихом разрыве новые подключения ожидают возврата связи.

## Конфигурация и схемы

Assets/Game/Configs/GameConfig.asset: поле 6×6, корабли 3/2/2/1, ход 15 секунд.
ConnectionConfig.asset: адрес, имя типа комнаты battle и параметры сети.
При создании комнаты клиент передаёт BoardSize, ShipLengths и TurnDurationSeconds из GameConfig.asset. Сервер проверяет значения и сохраняет правила этой комнаты; оба игрока получают их через Schema. Для изменения размера поля экспорт больше не нужен — создайте новую комнату. Настройки присоединяющегося игрока не меняют партию.
Server/config/game.json задаёт значения по умолчанию для клиентов без gameConfig и серверный ReconnectGraceSeconds. Меню SeaBattle → Export server configuration позволяет обновить эти серверные значения.
После изменения Server/src/rooms/schema/MatchState.ts выполните из Server `npm run export`.
Генерируемые C# в Assets/Game/Scripts/Multiplayer/Generated сохраняются в клиентском репозитории и вручную не редактируются.

## Проверка

`npm test` в Server: 15 тестов, включая полную партию, приватность, восстановление потерянного результата, сохранение отказов и истечение срока переподключения.
Unity Test Runner → EditMode → SeaBattle.Tests.EditMode: 36 тестов, включая двойной клик, перестановку ответа/патча, сохранение сессии, повтор команды, замену Schema, задержки/потери/дубликаты, фиксированный seed, отмену старых доставок и независимость вложенных снимков.
Через MCP проверены полные партии, обнаружение тихой потери heartbeat, пересоздание транспорта/сессии/модели при потерянном ответе и реальный перезапуск сцены во время выстрела. Сохраняются игрок и единственный выстрел; Console без ошибок и предупреждений.
Кнопки панели проверены в реальной партии: задержка 200±50 мс и 100% дубликатов не удваивают выстрел; после 100% потерь пересоздание клиента восстанавливает ожидающую команду. Проверены тихий обрыв, подключение, перезапуск сцены с задержками, переключение и очистка лога.

Если сервер сообщает, что комната удалена (4212), восстановление прекращается сразу, а сохранённый токен сбрасывается. Клиент показывает «Партия больше недоступна» и предлагает вернуться в меню. Неизвестный исход выстрела не объявляется отклонённым.

Итоги этапа 7 и воспроизводимые сценарии — [TESTING.md](TESTING.md). В EditMode есть ServerRegressionTests: он собирает актуальный TypeScript и запускает серверный набор. Для Run All нужны Node.js 22+ в PATH и зависимости Server после npm ci.
