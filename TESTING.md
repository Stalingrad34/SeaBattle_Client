# Проверки SeaBattle

## Автоматический запуск

Нужны Node.js 22+ в PATH и серверный репозиторий в папке Server с установленными зависимостями (`npm ci`).

- Сервер отдельно: из Server выполнить `npm test`.
- Весь набор из Unity: Test Runner → EditMode → SeaBattle.Tests.EditMode → Run All.

ServerRegressionTests сначала компилирует актуальный TypeScript, затем запускает тот же серверный набор. Правила не дублируются в C#. Запуск занимает около минуты; редактор остаётся отзывчивым. Серверные тесты используют временные свободные порты и закрывают собственные серверы. Пользовательский сервер на 2567 не затрагивается.

Проверено: **36 EditMode-тестов**, включая серверный запуск; **15 Node-тестов**, включая три вложенных сценария с разными seed.

## Пять рискованных сетевых сценариев

| Сценарий | Где проверяется | Ожидаемый результат |
| --- | --- | --- |
| Двойной клик, дубликат команды, потерянный ответ | BattlePopupTests, battle-rules.test, unreliable-network.test | Один выстрел; повтор возвращает сохранённый исход; новые выстрелы заблокированы до результата и Schema |
| Ответ и Schema в разном порядке, старые сообщения после нового хода | BattlePopupTests, ArchitectureTests, NetworkSimulatorTests | Старый ответ не завершает новую pending-команду, ревизия не откатывается |
| Пересоздание клиента/сцены с выстрелом в пути | ArchitectureTests, BattlePopupTests, NetworkSimulatorTests; реальная партия Unity | Сохраняются игрок и commandId; старые callbacks отменяются; итог выстрела восстанавливается |
| Тихий обрыв, возврат связи, одновременный разрыв у обоих игроков | NetworkSimulatorTests, reconnection.test; реальная партия Unity | Разрыв обнаруживается по heartbeat; приватное состояние и история команд сохраняются |
| Истечение срока восстановления и удаление комнаты | reconnection.test, BattlePopupTests; отдельная runtime-проверка удалённой комнаты | Отключившийся игрок проигрывает; удалённая комната не вызывает бесконечных попыток входа |

Правила дополнительно проверяются на 200 расстановках: прямые непрерывные корабли, запрет соприкосновения, границы поля, строгая очередность, дедлайн, потопление и победа. Проверяются также приватная Schema, sunkCells и параметры создателя комнаты.

## Полные партии при плохой сети

unreliable-network.test запускает настоящий Colyseus и двух сетевых клиентов. Seed: **7, 42, 2026**. На прикладные сообщения накладываются 25% потерь, 40% дубликатов и задержки 5–49 мс с возможной перестановкой. Корабли генерируются с фиксированным RNG только внутри теста. В конце сравнивается весь приватный снимок каждого клиента с авторитетным состоянием сервера, проверяются отсутствие повторных клеток и реальное наличие потерь/дубликатов.

Тест не повреждает бинарные дельты Colyseus: эмулируется доставка независимых снимков после декодирования, как в Unity NetworkSimulator. Повторный checkpoint восстанавливает потерянное последнее обновление.

## Ручная проверка в двух клиентах

1. Создать комнату и присоединиться вторым клиентом. Открыть «Отладка сети».
2. Задать задержку 120 мс, разброс 80 мс, потери 15%, дубликаты 35%, seed 42. При двойном клике должна отправляться одна новая команда.
3. Во время ожидания ответа нажать «Пересоздать клиент». Проверить возврат в тот же матч. После пересоздания эмулятор берёт исходные настройки из ConnectionConfig — при необходимости применить профиль снова.
4. Во время следующего выстрела перезапустить сцену. Проверить восстановление поля и отсутствие ошибок Console.
5. Нажать «Разорвать», дождаться обнаружения обрыва, затем «Подключить». Завершить партию и проверить согласованный итог и возврат в меню у обоих игроков.
6. Отдельно оставить клиента отключённым дольше серверного ReconnectGraceSeconds (120 секунд по умолчанию). После победы соперника выйти им в меню, затем восстановить связь проигравшего: должна появиться надпись о недоступной партии. Повторное подключение не должно отправлять запросы к удалённой комнате.

## Результат проверки Unity

Итоговая runtime-проверка 28.09.2026: настоящие кнопки Unity, отдельный Node-клиент и сервер на временном порту 2579. Unity: 120±80 мс, 15% потерь, 35% дубликатов, seed 42; второй клиент: 20% потерь и 40% дубликатов. Для ускорения проверки только в runtime-копии настроек использовались повтор выстрела через 2 секунды и обнаружение обрыва через 3 секунды. Выполнены пересоздание клиента и перезапуск сцены с pending-командой, тихий обрыв и восстановление, проверка единственного итогового попапа и возврат в меню.

Партия завершилась победой Unity: 36/35 выстрелов, revision=73. Весь PlayerState Unity и приватный снимок второго клиента совпали с сервером, включая корабли, входящие/исходящие выстрелы и sunkCells. Console без ошибок и предупреждений. Проверочные значения конфигов восстановлены, временный сервер остановлен. Кнопка отладки перенесена в левый верхний угол, чтобы не перекрывать «Выйти».

## Границы проверки

Автотесты проверяют несколько фиксированных сетевых последовательностей, а не все возможные комбинации событий. Проверка чистого запуска из репозиториев, подготовка финальных материалов и видео относятся к этапу 8. Сохранение партий после перезапуска серверного процесса не реализовано.
